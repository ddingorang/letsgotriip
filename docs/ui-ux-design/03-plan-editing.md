# 03. 여행(계획) 수정 UX 개선

사용자 피드백: "여행 수정 부분이 좀 불편해."

## 진단 (개선 전)
PlanView의 계획 편집에서 가능한 것은 **(1) 같은 일차 내 순서 변경 + (2) 장소 삭제**뿐.
- ❌ **장소 추가 불가** — 새 장소를 넣으려면 AI 챗봇으로 나가서 "○○일차에 △△ 추가해줘"라고 해야 했음(가장 큰 불편).
- ❌ 일차 간 이동 불가 (드래그는 같은 일차 내로 제한)
- ❌ 방문 시간/메모 인라인 편집 불가

## 1차 구현 — 일차별 "장소 추가" (채택)
- 각 일차 일정 목록 끝에 **"N일차에 장소 추가"** 점선 버튼.
- 누르면 **검색 바텀시트**: 장소 이름 검색(`GET /api/attractions?keyword=&size=15`) →
  결과(썸네일·이름·주소) 탭하면 `planStore.addPlace(planId, dayNo, {contentId, contentType})`로 즉시 담김.
- 추가 후: 상세 재조회(store) + **도로 경로 재계산** + 추가한 일차를 지도에 표시.
- 빈 결과/에러/중복(`이미 계획에 있어요`) 상태 처리. 모바일 바텀시트(safe-area) 패턴 재사용.

검증: 검색 API가 `contentId`·`contentTypeId`·`firstimage`를 정상 반환함을 확인. 빌드 통과.

## 안전장치
- 포인터 드래그(터치+마우스) window 리스너를 `onUnmounted`에서 정리(드래그 중 이탈 시 누수 방지).

## 다음 후보 (검증 후 진행 권장)
- **일차 간 드래그 이동** (1일차 → 2일차): `replacePlaces`를 두 일차에 순차 호출해야 하는데
  낙관적 잠금(expectedVersion)이 걸려 있어, 첫 호출 후 버전 갱신을 보장한 뒤 두 번째를 호출해야 함 → 신중 구현.
- **방문 시간 인라인 편집**: 장소별 시간 픽커 → `replacePlaces`로 저장.
- 둘 다 상태 일관성 리스크가 있어 단독 검증 후 붙이는 것을 권장.
